## Context

T5.1/T5.2/T5.3 built the pure functions (`run_backtest`, `benchmark_curves`,
`compute_metrics`, `render_report`) but there is no entrypoint that wires them
together on real data. T4.4 produced the calibrated `p_up` in
`data/processed/panel_calibrated.parquet`. Run the backtest and produce the
T5.3 deliverable `docs/reports/backtest.md`.

## Objective

Wire the existing modules into a runnable command and produce the backtest
report on the real calibrated panel.

## Implementation notes

- Add an entrypoint (e.g. `python -m pressflow.backtest_run`, or a `run()` +
  `__main__` in an existing module) that:
  1. loads `data/processed/panel_calibrated.parquet` (has `date`, `ret_simple`,
     `p_up`) and `data/processed/prices.parquet`;
  2. `run_backtest(panel, cfg)` → backtest frame (exactly `BACKTEST_COLUMNS`);
  3. `benchmark_curves(prices, backtest_df[DATE])` → {spy, otp, cash};
  4. `compute_metrics(backtest_df, benchmarks, prices)`;
  5. `render_report(backtest_df, benchmarks, prices)` → `docs/reports/backtest.md`
     + plots (`equity.png`, `drawdown.png`, `position.png`).
- Write `data/processed/backtest.parquet` with `BACKTEST_COLUMNS` (data dir is
  gitignored).
- Read `kelly` (k=0.25, shrink_gamma=0.5, cap=1.0) and `costs.base=0.003` from
  `get_config()`.
- Report the metrics table (strategy vs SPY vs OTP vs cash: total return, CAGR,
  Sharpe, max drawdown, hit rate, turnover, trades). State the result plainly —
  if the strategy underperforms the benchmarks, say so without editorializing.

## Acceptance criteria (DoD)

- [ ] `data/processed/backtest.parquet` written with `BACKTEST_COLUMNS`.
- [ ] `docs/reports/backtest.md` exists with the metrics table + 3 plots.
- [ ] Metrics are honest (strategy vs benchmarks, no over-claiming).
- [ ] `uv run pytest -q` still passes (no regression).
