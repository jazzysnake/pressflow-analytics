## Context

T4.4 verification returned PASS WITH ISSUES: the implementation is correct
(strict `valid[:i]` walk-forward, shrink-once, Brier numbers reproduce), but the
tests credited with enforcing the two headline guarantees do not fully enforce
them, and the report understates that calibration does not beat climatology.
Fix before merging.

## Objective

Make the tests actually enforce no-lookahead and no-double-shrink, and state the
Brier result honestly.

## Implementation notes

On branch `t4.4-calibration`, commit on top of `0e6be05`:

1. **No-lookahead test (major)** — `tests/test_calibration.py`
   `test_no_lookahead_ignores_future_rows` catches *future*-row leakage but
   would **not** fail if `walk_forward_p_up` fit on row `t` itself
   (`valid[:i+1]`). Add a mutation test: flip row `t`'s own `up` label and
   assert the prediction for row `t` is unchanged
   (`walk_forward_p_up(panel)[t] == walk_forward_p_up(panel_with_t_label_flipped)[t]`).
   The test must fail under a `valid[:i+1]` implementation.
2. **No-double-shrink test** — `test_backtest_consumes_raw_p_up_not_pre_shrunk`
   never calls `calibrate_panel`. Add an assertion that
   `calibrate_panel(panel)[P_UP]` equals the raw `walk_forward_p_up` output
   (i.e. calibrate does not pre-shrink `p_up`).
3. **Optional-dep guard** — add `pytest.importorskip("sklearn")` (or declare
   sklearn in the dev group) so sklearn-dependent tests don't fail on a clean
   `uv sync`.
4. **Report wording** — in `docs/reports/calibration.md`, state plainly that the
   calibrated Brier (0.2497) is not better than climatology (0.2493), and add
   the prediction span ≈ [0.48, 0.58].

## Acceptance criteria (DoD)

- [ ] No-lookahead test fails under a `valid[:i+1]` (fits row `t`) implementation.
- [ ] No-double-shrink test exercises `calibrate_panel`.
- [ ] `uv run pytest -q` passes.
- [ ] Report states the Brier-vs-climatology result honestly.
