## Context

Epic 01 was verified **PASS WITH ISSUES**. Five minor, non-data-corrupting
issues were found by the verifier. Fix these before (or alongside) the full
10-year crawl.

## Objective

Resolve the five issues below.

## Issues to fix

1. **Exact checkpoints not recorded + wrong test band.** The real 10-year start
   page is `oldal=50666` (target 2016-10-01), but `tests/test_forum_pagination.py`
   asserts a `40_000..47_000` band and a `~43,000` docstring. Record the exact
   value and fix the test band.
2. **Probe pages re-fetched in `--full`/`--target-date`.** Binary-search probe
   pages (~log₂(max) ≈ 16) are fetched twice (once by the search, once by the
   crawl loop). Reuse/cache probed pages into the crawl queue so no page is
   fetched more than once per run (T1.4 DoD).
3. **Unreachable deleted-user fallback.** `parser.py` uses `.commentdata i`,
   which never matches live markup (`<span>Törölt felhasználó</span>`). Fix the
   selector to the real markup or remove the fallback (and its test).
4. **`--fresh` does not clear `parts_dir`.** Stale part files are then deduped
   against / overwritten. `--fresh` should clear `parts_dir` for a clean run.
5. **Dropped-record counts not surfaced.** Null `ts`/`text` (and no-vote-span)
   comments are dropped before write, so the T1.5 ≥95% text/ts thresholds can
   never fail. Report skipped/dropped-comment counts in the validation report.

## Acceptance criteria (DoD)

- [ ] Each issue addressed, with a unit test where applicable.
- [ ] `uv run pytest` passes.
- [ ] `uv run python -m pressflow.forum.crawler --pages 10 --fresh` runs from a
      clean state and a resume re-run fetches no duplicates.
