## Context

Forum timestamps come in three raw forms: relative `ma, 21:09` ("today"),
`tegnap, 14:30` ("yesterday"), and absolute `2010. 11. 25. 10:17`. They must
become tz-aware Europe/Budapest datetimes.

## Objective

Convert any raw timestamp string to a tz-aware `datetime`.

## Implementation notes

- "Now" must come from the **HTTP `Date` header of the request that fetched the
  page**, not a process-global clock — pages fetched around midnight can
  otherwise mislabel `ma`/`tegnap`.
- Rules:
  - `ma, HH:MM` → now.date() at HH:MM (Europe/Budapest).
  - `tegnap, HH:MM` → now.date() − 1 day at HH:MM.
  - absolute → regex `^(\d{4})\.\s*(\d{1,2})\.\s*(\d{1,2})\.\s*(\d{1,2}):(\d{2})$`.
- Return `datetime` with `tzinfo=ZoneInfo("Europe/Budapest")`.
- Invalid/unparseable → return `None` (and count it in T1.5), never throw.

## Acceptance criteria (DoD)

- [ ] Unit tests for all three formats.
- [ ] A midnight-boundary test (page fetched 00:10 BUD) resolves `ma` correctly
      relative to the header date.
- [ ] Output is tz-aware Europe/Budapest.
