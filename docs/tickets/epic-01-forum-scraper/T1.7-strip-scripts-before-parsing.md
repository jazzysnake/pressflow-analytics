# T1.7 — Strip scripts/styles before parsing

| Field | Value |

## Context

Measured on a live page (2026-10): each forum page is ~13.6 MB of HTML, and
`BeautifulSoup(html, "lxml")` takes **~1.45s** of that (~1.9s total incl.
0.44s fetch + 0.35s politeness delay). At 15,000 pages that's ~8–9 hours for
the full crawl. All required post fields live in the comment DOM; the bulk of
the page is `<script>`/`<style>` and other non-comment markup.

## Objective

Strip `<script>`/`<style>` (and other non-comment nodes) *before* parsing so
the full crawl drops to ~3.5–4 hours.

## Implementation notes

- In `src/pressflow/forum/parser.py`, before `BeautifulSoup(html, "lxml")`,
  remove `<script>…</script>` and `<style>…</style>` blocks (and optionally
  `<link>`, `<noscript>`, `<svg>`, HTML comments).
- Prefer a robust regex removal for script/style (their content is CDATA-like,
  not parsed HTML, so regex is safe here) — but guard against `</script>` /
  `</style>` appearing inside JS strings if cheap; correctness is what matters.
- **Do NOT change the extracted fields.** Every one of the 11 `POSTS_SCHEMA`
  fields must still be extracted identically from the fixture and a live page.
- Benchmark before/after on ONE real live page (a single fetch is fine):
  record `parse` time before (≈1.45s) and after (target <0.3s) in the commit
  message / PR report.

## Acceptance criteria (DoD)

- [ ] Existing parser tests still pass unchanged (all fields extracted).
- [ ] A new test asserts the pre-processed HTML contains the comment nodes but
      no `<script>`/`<style>` tags.
- [ ] Manual benchmark on a real 13.6 MB page shows parse time ≤ 0.3s (report
      the before/after numbers).
- [ ] `uv run pytest` passes.
