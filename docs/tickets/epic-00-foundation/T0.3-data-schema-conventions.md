## Context

Parquet artifacts flow between stages (scrape → sentiment → signal → backtest).
Schemas must be defined once and shared, or downstream tasks will guess column
names and types.

## Objective

Define and document the Parquet schemas for every stage.

## Implementation notes

Write `docs/schema.md` and matching Python constants (e.g., a `Schema` class or
`pyarrow.schema` definitions). Minimum columns:

- **posts** (`data/processed/posts.parquet`): `post_id int`, `hsz_id int`,
  `author str`, `user_id int`, `ts datetime[tz=Europe/Budapest]`,
  `reply_to_post_id int?`, `reply_to_hsz_id int?`, `upvotes int`,
  `downvotes int`, `text str`, `page int`.
- **prices** (`data/processed/prices.parquet`): `date`, `otp_close_huf`,
  `otp_adj_close_huf`, `usdhuf`, `spy_adj_close_usd`, `spx_close`, plus derived
  `otp_usd`, `spy_usd` (see T2.2).
- **scores** (`data/processed/scores.parquet`): `hsz_id int`, `model str`,
  `p_bull float`, `p_bear float`, `p_neutral float`, `net float`.
- **signals** (`data/processed/signals.parquet`): `date`,
  `score_wmean`, `bear_wmean`, `count`, `disagreement_std`, `entropy`,
  `z_score`.
- **backtest** (`data/processed/backtest.parquet`): `date`, `position`,
  `ret`, `cost`, `equity`.

## Acceptance criteria (DoD)

- [ ] `docs/schema.md` exists and documents every column + unit.
- [ ] Python schema constants match the docs.
- [ ] Each schema has a `hsz_id`-based natural key where applicable (dedupe).
